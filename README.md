# TableBDR — Budget Management Table with PostgreSQL

A React + TypeScript + Webpack project with a collapsible budget table connected to PostgreSQL. Displays telecom and connectivity service budgets with expandable row groups.

## 🧭 Начало

Сводный дашбоард по проекту:

- **Стек:** React 19, TypeScript, Webpack, Express, PostgreSQL
- **Запуск:** `npm install` → создать `.env` → `npm run server` → `npm run dev`
- **Фронтенд:** `src/` (`App.tsx`, `BudgetTable.tsx`, `main.tsx`)
- **Бэкенд:** `server/` (`index.ts`, API `/api/*`, `GET /api/health`)
- **Скрипты:** `scripts/testPostgresConnection.ts`, seed/инициализация БД
- **Схема БД:** GN/PAO таблицы (`GN_bdr`, `GN_department`, `GN_dogovor`, и т.д.)
- **Особенности:** коллапсируемые строки, HMR, строгий TypeScript, ESLint, dev proxy `/api/*`
- **Сборка:** `npm run build` → результат в `dist/bundle.js`

# TableBDR

TableBDR - веб-система для ведения и анализа бюджетных данных (БДР) по направлениям связи и смежным сущностям: подразделения, договоры, контрагенты, объекты, лимиты и спутниковые/сотовые сервисы.

## Назначение

Проект предоставляет единый интерфейс для:

- просмотра бюджетных таблиц с детализацией по разным срезам;
- перехода к карточкам связанных сущностей (договор, подразделение, объект и др.);
- анализа агрегированных показателей по подразделениям и бюджетным статьям;
- работы с доменными данными, загружаемыми и хранимыми в PostgreSQL.

## Архитектура

Приложение состоит из двух частей:

- Frontend (React + TypeScript + Webpack): отвечает за маршрутизацию, таблицы, карточки и аналитические представления.
- Backend (Express + TypeScript): предоставляет API для чтения/подготовки данных и интеграции с PostgreSQL.

Во время разработки frontend и backend запускаются раздельно, при этом frontend работает через проксирование API-запросов к backend.

## Предметные модули

- Бюджетный контур: таблица БДР, детализация по подразделениям и статьям, сводные представления.
- Главная страница: сводка по подразделениям и объектам по умолчанию свёрнута и загружается при раскрытии; расходы по услугам и стоимость оборудования отображаются в соответствующих столбцах с итогами. Плитка «Первичные» показывает по месяцам долю строк с включенным флажком «Запущен в СЭД» и число отмеченных строк из общего количества. Вариант БДР выбирается в Личном кабинете АДМ.
- Контракты: страницы списка и детальной информации по договорам.
- В деталях договора лицевой счёт выбирается отдельно для каждой строки сводной таблицы БДР и отображается в таблице «БДР Услуги связи». При первом обновлении существующим строкам назначается счёт, только если он у договора единственный.
- Первичные: реестр первичных документов со связями на подразделения, объекты, статьи бюджета и договоры.
- Заметки: общее пространство с блокнотами, разделами, страницами, форматированием, тегами и поиском.
- Инвест-программа: отдельная таблица и связанные сценарии анализа.
- Учет оборудования: последние 50 изменений журнала хранятся в PostgreSQL и доступны между браузерами.
- Спутниковые сервисы: контроль и детализация спутниковых данных.
- Сотовая связь: отдельный экран и справочник тарифов.

## API

Backend предоставляет REST-эндпоинты в пространстве `/api/*`.

Реестр «Первичные» доступен по адресу `#primary`; записи обслуживаются через `/api/primary`. Контрагента можно выбрать в режиме редактирования общих полей; при выборе подставляется связанный договор, который при необходимости можно уточнить в столбце «Договор». Лицевой счет для договора задается в справочнике договоров. Карандаш в первом столбце редактирует общие поля; месячные значения редактируются отдельно и хранятся независимо для каждого месяца. Прежние значения детализации сохраняются в базе. В раскрытом месяце доступны флажок «Запущен в СЭД» и растягиваемое поле примечания. Карандаш рядом с кнопкой раскрытия переводит все строки выбранного месяца в режим редактирования, включая ранее пустые ячейки; повторное нажатие сохраняет месячные поля всех строк одной операцией. Пустая сумма остается пустой, а редактирование месяца меняет только его значения, без общих столбцов и данных других месяцев. Для существующих записей прежние сумма, отметка СЭД, примечание и даты переносятся в соответствующий месяц; старые значения в базе сохраняются. Подразделение выбирается над таблицей: отдельно для фильтра и для редактируемой записи. При создании месяц документа меняется нажатием «Выбрать» в ячейке нужного месяца; введённые данные переносятся в него.

В новых выборах подразделения, объекта, контрагента и договора используются значения из активных строк «БДР Услуги связи». Объекты ограничены выбранным подразделением; контрагенты — строками БДР выбранного подразделения и хотя бы одного из выбранных объектов; договоры — выбранным контрагентом. «Газпром телеком» на выбор не влияет. Ранее сохранённые значения остаются доступными при редактировании.

Фильтр подразделения над таблицей содержит только подразделения, встречающиеся в записях «Первичные».

При редактировании месяца флажок «Принято на учет в 1С» доступен только при установленном флажке «Запущен в СЭД» в той же строке. Снятие отметки СЭД не изменяет ранее установленную отметку 1С.

Ячейки каждого месяца окрашиваются по его отметкам: без отметок — светло-красным, только СЭД — светло-жёлтым, обе отметки — светло-зелёным. Сочетание отметки 1С без СЭД не окрашивается.

Панель над таблицей сбрасывает фильтры, выгружает отфильтрованные строки в Excel и загружает Excel. Выгрузка включает настоящий ID записи и данные всех месяцев. При загрузке выбираются лист, один месяц и столбцы; заголовки находятся в первой строке. Строки с ID обновляются, строки без ID добавляются; остальные записи и месяцы не меняются. Пустая ячейка сопоставленного столбца очищает значение (для флажков означает «нет»), несопоставленные столбцы сохраняются. Несколько объектов разделяются точкой с запятой; неизвестные и неоднозначные значения отклоняются. Контрагент используется для проверки договора, а вычисляемые столбцы «На кого расходы» и «БДР26корр» не импортируются. Ошибка в любой строке отменяет всю загрузку.

При выборе предыдущих полей единственный доступный объект, контрагент, договор или лицевой счёт выбирается автоматически.

Столбец «На кого расходы» показывает подразделения расходов из активных строк БДР по договору, подразделению записи и выбранным объектам. Значения редактируются в деталях договора и не дублируются в первичном документе.

«БДР26корр» показывает сумму значений из тех же строк БДР.

Лицевой счёт в таблице «Первичные» открывает окно детализации с загрузкой XML-файла в память браузера. Правила обработки и расчёта пока не определены; файл не сохраняется и не отправляется на сервер.

Заметки доступны по адресу `#notes`; их данные хранятся в PostgreSQL. Редактор поддерживает заголовки, форматирование и выравнивание текста, шрифты и размеры, цвета и выделение, ссылки HTTP(S) и mailto, цитаты, код, списки задач и таблицы. Для ссылки выделите текст и нажмите «Ссылка»; пустой адрес удаляет ссылку. Таблица вставляется размером 3×3, строки и столбцы можно добавлять и удалять с панели редактора. Изображения и файлы не поддерживаются.

Базовая проверка доступности сервиса:

- `GET /api/health`

## NPM-скрипты проекта

Скрипты отражают доступные режимы разработки и сборки:

- `server-dev` - запуск backend в режиме разработки.
- `front-dev` - запуск frontend dev-сервера.
- `build-front` - production-сборка frontend.
- `build-server` - компиляция backend TypeScript.
- `test:db` - проверка подключения к PostgreSQL.
- `lint` - статический анализ кода.

## Примечания

- Проект содержит отдельный серверный подпакет в `server/`, но основной контур разработки централизован через корневой `package.json`.
- Для интеграции с БД используются параметры окружения (`PGHOST`, `PGPORT`, `PGUSER`, `PGPASSWORD`, `PGDATABASE`, `SERVER_PORT`).
